Guia das telas do Orion Service

Um material para os integrantes do grupo entenderem e apresentarem o site, mesmo sem conhecer programação.

O Orion Service é uma central de suporte para equipamentos. A proposta é ajudar o usuário a consultar máquinas, procurar orientações sobre problemas e registrar pedidos de atendimento. Um chamado é justamente um pedido de ajuda registrado no sistema.

Este guia explica a versão atual do site. As informações de clientes e equipamentos são fictícias e usadas no trabalho da faculdade. As páginas antigas de clientes, negociações e atividades pertencem a outro protótipo e não fazem parte do fluxo descrito aqui.

Para apresentar com segurança: algumas funções já funcionam de verdade, como pesquisar equipamentos e salvar chamados. Outras mostram apenas como o sistema poderá funcionar, como o login e a tela fixa de solução. As diferenças estão indicadas em cada seção.

Como se orientar no site

No computador, o menu fica à esquerda. Ele permite trocar de tela. No celular, a navegação aparece por ícones na parte inferior. O título no alto indica onde o usuário está. Nas telas internas, o botão Voltar retorna à tela anterior; quando a tela foi aberta diretamente, retorna ao Dashboard. As setas de voltar e avançar do navegador também acompanham a navegação entre as telas.

A seta circular na borda do menu permite recolher ou expandir a navegação no computador. Recolhido, o menu mostra apenas os ícones; passe o mouse ou use o teclado para ver o nome de cada tela. A escolha fica salva nesse navegador. As animações acompanham a entrada das telas e as interações, respeitando a preferência de movimento reduzido do dispositivo.

Os blocos com informações de equipamentos são chamados de cartões. As etiquetas coloridas indicam a situação de um equipamento ou chamado. O nome “João Silva”, no cabeçalho, é um exemplo fixo. O ícone de notificação e a indicação ao lado do nome ainda não abrem funções.

Entrar → consultar equipamentos → procurar uma solução → abrir um chamado → acompanhar o registro

1 Login

Para que serve: representar a entrada do usuário na central de suporte.

O que aparece: apresentação do Orion Service, campos de CPF e senha, “Esqueci minha senha” e botão “Entrar”.

Como demonstrar: preencha os dois campos com dados fictícios e clique em Entrar. O site abre o Dashboard.

Na versão atual: o sistema exige que os campos estejam preenchidos, mas não verifica se o CPF e a senha são verdadeiros. A recuperação de senha ainda não funciona. Não use dados pessoais ou senhas reais para demonstrar.

Sugestão de fala“Esta é a entrada da central de suporte. No protótipo, simulamos o acesso para apresentar as telas.”

2 Dashboard

Para que serve: mostrar um resumo rápido. “Dashboard” significa painel de acompanhamento.

O que aparece: quantidade total de equipamentos, equipamentos operacionais, equipamentos com atenção e chamados com status “Aberto”. Abaixo, aparecem os três primeiros equipamentos da lista.

  • Ver todos: abre “Meus equipamentos”.
  • Ver equipamento: abre a tela de detalhes.
  • Consultar equipamento: também abre a tela de detalhes.

Na versão atual: os indicadores são calculados com os registros do banco. O total de chamados abertos não inclui os que estão “Em atendimento”. Apesar dos textos “meus equipamentos”, os dados apresentados são os dados gerais de demonstração, sem separação por usuário.

Sugestão de fala“Este painel resume a situação dos equipamentos e dos chamados. Os números vêm dos registros armazenados no banco.”

3 Meus equipamentos

Para que serve: consultar os equipamentos disponíveis no sistema.

O que aparece: cartões com nome, modelo, número de série e situação. O número de série identifica uma unidade específica do equipamento.

  • Pesquisar equipamento: digite parte do nome, como “Hunter”. A busca procura pelo nome, não pelo número de série.
  • Filtro de situação: escolha Todos, Operacional, Atenção ou Parado.
  • Ver equipamento: abre os detalhes de demonstração.

Como demonstrar: pesquise “Target”, depois apague a busca e selecione “Parado”. Para ver tudo novamente, limpe a busca e escolha “Todos”.

Na versão atual: a busca e o filtro funcionam. Não há botões para cadastrar, editar ou excluir equipamentos nessa tela.

Sugestão de fala“Aqui podemos localizar uma máquina pelo nome e filtrar os equipamentos pela situação.”

4 Detalhes do equipamento

Para que serve: reunir informações de uma máquina e oferecer caminhos para procurar ajuda.

O que aparece: nome, modelo, situação, ano, número de série, fabricante e versão. Há seis categorias de ajuda: pressão, vazão, elétrica, mecânica, aplicação e outros problemas.

Como demonstrar: entre pelo primeiro Orion Hunter e clique em “Problemas de pressão”. O site abre a Base de conhecimento.

Na versão atual: todos os botões “Ver equipamento” mostram o mesmo exemplo: Orion Hunter, série HTR24-00145. As seis categorias levam à mesma lista de problemas; ainda não existe filtro por categoria.

Sugestão de fala“Esta tela demonstra como reunimos os dados da máquina e o acesso às orientações de suporte.”

5 Base de conhecimento

Para que serve: reunir problemas conhecidos e suas possíveis causas para orientar o usuário antes de solicitar atendimento.

O que aparece: uma lista com o título do problema, uma descrição curta, a possível causa e o botão “Ver solução”.

Como demonstrar: escolha o primeiro item, “Baixa pressão durante a aplicação”, e clique em Ver solução.

Na versão atual: a lista é consultada no banco. Embora o subtítulo indique “Problemas de pressão”, a tela mostra todos os problemas cadastrados. Todos os botões “Ver solução” abrem o mesmo exemplo de baixa pressão.

Sugestão de fala“A base de conhecimento reúne problemas e possíveis causas. Para demonstrar o passo a passo, vamos usar o exemplo de baixa pressão.”

6 Solução

Para que serve: apresentar uma sequência de orientações para o problema escolhido.

O que aparece: o exemplo de baixa pressão, uma possível causa, quatro passos de verificação e um aviso para procurar suporte se o problema persistir. O conteúdo é demonstrativo, não um diagnóstico automático.

  • Problema resolvido: abre a lista “Meus chamados”.
  • Não resolveu: abre o formulário para registrar um chamado.

Na versão atual: clicar em “Problema resolvido” não altera o status de nenhum chamado. O botão apenas troca de tela. A solução mostrada é fixa, e suas quatro instruções vêm do banco.

Sugestão de fala“O usuário recebe orientações e, caso ainda precise de ajuda, pode seguir para a abertura de um chamado.”

7 Abrir chamado

Para que serve: registrar um pedido de atendimento. Esta é uma das funções que já gravam informações no banco.

O que preencher: cliente, equipamento, problema, descrição do ocorrido e prioridade Baixa, Média ou Alta.

  1. Selecione um cliente, um equipamento e um problema nas listas.
  2. Escreva uma descrição. Exemplo: “Durante o teste, a pressão ficou abaixo do esperado. Solicito avaliação da equipe.”
  3. Escolha a prioridade e clique em Abrir chamado.
  4. Aguarde o salvamento. Se der certo, o site abre “Meus chamados”. Se houver erro, a mensagem aparece no formulário.

Na versão atual: o novo chamado recebe um número, a data de abertura e o status “Aberto”. Ele permanece salvo depois de atualizar a página ou reiniciar o sistema. Confira as seleções: elas não são preenchidas a partir do equipamento ou problema que você visitou antes.

Sugestão de fala“Agora estamos registrando um pedido de suporte de verdade no banco do projeto. O chamado ficará salvo para consulta.”

8 Meus chamados

Para que serve: consultar os pedidos de atendimento registrados.

O que aparece: número do chamado, equipamento, problema, data e status. Os registros são apresentados do maior número para o menor, então um chamado recém-criado aparece no início.

  • Aberto: solicitação registrada.
  • Em atendimento: indica que o atendimento está em andamento.
  • Resolvido: indica que o atendimento foi concluído.

Como demonstrar: localize o chamado que acabou de criar. O botão + Abrir chamado permite registrar outro pedido.

Na versão atual: a tela consulta os registros, mas não oferece edição de status, exclusão ou abertura de detalhes de um chamado. Os status dos exemplos antigos já estavam cadastrados. No celular, algumas colunas ficam ocultas para caber na tela.

Sugestão de fala“Nesta lista, o usuário consulta os chamados registrados e a situação informada em cada um.”

9 Painel administrativo

Como acessar: clique em Acesso admin, no canto inferior direito, depois de entrar no site.

Para que serve: mostrar uma visão geral para quem acompanha o atendimento.

O que aparece: totais de clientes e equipamentos, chamados abertos e em atendimento, além de uma lista com chamado, cliente, equipamento, problema e status. “Voltar ao cliente” retorna ao Dashboard.

Na versão atual: os números vêm do banco. Alguns chamados antigos mostram “Não informado” no cliente porque esse vínculo não existia nos dados originais. Não há senha administrativa nem separação real de permissões; qualquer pessoa que entrou na demonstração consegue abrir esse painel.

Sugestão de fala“O painel administrativo reúne os indicadores e os chamados para facilitar a visão geral do atendimento.”

10 Banco de dados

Para que serve: guardar os registros usados no site. Pense nele como um conjunto de tabelas organizadas e conectadas: clientes, equipamentos, problemas, passos de solução e chamados.

Para a apresentação do grupo: vocês podem mostrar o banco separadamente no DBeaver, abrindo a conexão SQLite com o arquivo database/orion.sqlite. Não é necessário apresentar o banco dentro do site. Se o DBeaver já estiver aberto quando um chamado for criado, atualize a consulta para ver o novo registro.

Acesso separado: o banco não tem uma tela no menu do site. A consulta das tabelas para a apresentação deve ser feita no DBeaver. O site continua usando o banco para carregar informações e salvar chamados.

Palavras que podem aparecer: ID é o número que identifica um registro; PK é a identificação principal; FK é uma referência a outro registro; NULL significa que a informação não foi preenchida. “resumo_chamados” é uma consulta que reúne dados de mais de uma tabela, e não uma sexta tabela de cadastro.

Sugestão de fala“O site é a parte que o usuário vê. O banco guarda as informações. Quando abrimos um chamado, podemos conferir o mesmo registro aqui no DBeaver.”

Roteiro para apresentar em grupo

Uma divisão possível é separar a explicação em quatro partes. Ajustem conforme o número de integrantes; cada pessoa pode estudar apenas as telas da sua parte e ensaiar a passagem para a próxima.

Sequência curta para ensaiar

  1. Entre no site com dados fictícios e explique o Dashboard.
  2. Pesquise “Hunter” em “Meus equipamentos” e abra o primeiro equipamento.
  3. Entre em “Problemas de pressão”, escolha o primeiro problema e mostre a solução.
  4. Clique em “Não resolveu” e preencha um chamado de demonstração.
  5. Mostre o novo registro em “Meus chamados”.
  6. Abra o painel administrativo e, depois, confira o registro no DBeaver.

Antes da apresentação: combinem quem vai controlar o mouse, quem vai falar em cada parte e quem ficará responsável por ligar o sistema. Ensaios que salvarem chamados acrescentarão registros ao banco; os totais podem mudar.

Perguntas que podem surgir

Como ligar o site

No computador com o projeto já preparado, o integrante responsável abre o terminal na pasta do projeto e executa npm.cmd run dev. Depois, abre http://localhost:5173 no navegador e mantém o terminal aberto. “Localhost” significa que o site está rodando naquele computador; esse endereço não é um link público para os demais integrantes.

O que acontece ao atualizar a página ou clicar em Sair

Atualizar a página mantém a tela indicada no endereço do navegador. Clicar em “Sair” retorna ao login. Nenhuma dessas ações apaga os chamados gravados. Nesta demonstração, não existe uma sessão de usuário autenticada.

Por que o site não abriu

Confira se o terminal continua aberto e se o servidor iniciou sem erros. Se aparecer uma mensagem de falha de conexão com o banco, peça ao integrante responsável para conferir o sistema e depois use “Tentar novamente”.

Precisamos explicar código

Não é necessário para demonstrar a interface. Basta entender o caminho: a pessoa preenche uma tela, o sistema recebe a solicitação, guarda o registro e o apresenta nas listas. Se perguntarem sobre a estrutura, expliquem que React monta as telas, Node.js recebe as solicitações e SQLite guarda os dados.

O sistema já está pronto para um cliente real

Ainda é um protótipo acadêmico. Para uso real, faltam autenticação, permissões por usuário, detalhes e soluções específicos para cada seleção, além da preparação da hospedagem e dos backups. O grupo pode apresentar as funções existentes sem afirmar que essas etapas já estão concluídas.
